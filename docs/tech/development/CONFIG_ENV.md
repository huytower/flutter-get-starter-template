# Environment Configuration Guide

How build-time settings (API URL, feature flags, webhooks, model names) reach the app.

## Single source of truth

| Where | What |
|---|---|
| GitHub **Repository Variables** | Non-secret values (`APP_NAME`, `API_URL`, `ENABLE_*`, paths, versions) |
| GitHub **Repository Secrets** | Secret values (`SLACK_*_WEBHOOK_URL`, `GEMINI_MODEL_NAME`, force-update defaults) |
| `env/prod.example.json` (committed) | The list of keys, with sample values. A key not listed here is never passed to the app. |
| `env/prod.json` (git-ignored) | The real values for one build: generated by CI, or a local copy of the example |
| Firebase Remote Config | Values that must change **without a new build** (e.g. forced update `isForce`) |

## Flow

```
GitHub Variables + Secrets
  -> CI step "Generate App Env" writes env/prod.json (key names logged, values never)
  -> flutter build ... --dart-define-from-file=env/prod.json   (values compiled in)
  -> PrjEnv (modules/app_config) reads them as const String/bool.fromEnvironment
  -> initEnv() (app shell, first boot step) -> CcSdkConfig.configure(...),
     CcSlackHandler / CcSlackFeedbackHelper / CcGeminiHelper.configure(...)
```

- `PrjEnv` is the **only** code that reads these keys; a missing key falls back to the default declared there.
- The SDK (`cc_core_sdk`) never reads env files or `--dart-define` keys; it receives typed values
  (`CcSdkConfig`). `CcFeatureFlags`, `CcRouteConfig`, `CcAppTrackName`, `CcCrashLogEnv` are read-only views of it.
- There is no `.env` file and no `flutter_dotenv` dependency any more.

## Local setup

```powershell
Copy-Item env/prod.example.json env/prod.json   # then edit values
flutter run -d <device> --flavor prod -t lib/main_prod.dart --dart-define-from-file=env/prod.json
```

VS Code's `Prod App` launch configuration already passes `--dart-define-from-file=env/prod.json`.

## Adding a setting

1. Add the key with a sample value to `env/prod.example.json`.
2. Add a `const` field to `PrjEnv` with a sensible default.
3. If the SDK needs it, add a field to `CcSdkConfig` (submodule) and pass it in `initEnv()`.
4. Set the value in GitHub: a Variable, or a Secret if it is sensitive. A new Secret must also be passed into
   `.github/actions/flutter-setup` (input + `env:` of the "Generate App Env" step) and added to its
   `secret_keys` set.

## Security note

Anything compiled into an app can be extracted from the binary; `--dart-define` only avoids shipping a plain-text
asset. Values that must stay secret (e.g. Slack webhooks) belong behind a server-side proxy.
